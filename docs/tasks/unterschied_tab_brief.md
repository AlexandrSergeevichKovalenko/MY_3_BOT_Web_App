# Вкладка «Отличия» — чем одно похожее слово отличается от другого

Макет всех экранов: https://claude.ai/code/artifact/07955095-d258-47b9-a290-f06c8b359921
Решения приняты владельцем 25.08.2026 в разговоре, здесь они записаны, чтобы не переспрашивать.

## Что делаем человеческим языком

Человек вбивает два-четыре похожих слова — `Anzahlung`, `Vorauszahlung`, `Vorschuss` — и получает
разбор: чем они отличаются, когда какое берут, где на этом спотыкаются русскоязычные. Каждое слово
и каждое готовое сочетание можно сохранить в словарь одним нажатием, не уходя с экрана.

## Что решено

| Вопрос | Решение владельца |
|---|---|
| Где живёт | В ОБОИХ словарях: быстрый (`DictionaryOverlay.jsx`) и внутренний (`App.jsx`) |
| Название вкладки | «⚖️ Отличия». «Мои слова» сокращается до «Слова» — иначе четыре подписи не влезают |
| Сколько слов | Две ячейки, кнопкой до четырёх |
| После разбора | Общий кеш на всех + личная история сравнений в той же вкладке |
| Лимит | Free: 3 НОВЫХ пары в день. Открыть уже разобранное — бесплатно и без счёта |
| Порядок блоков | Главное → замена → слова → примеры → когда какое → ошибки → сочетания |
| Кнопка у слова | «Сохранить» (не «＋ в мои слова») |
| Сочетания | Нажимаются, сохраняются ЦЕЛИКОМ как фраза: «eine Anzahlung leisten — внести задаток» |
| Внизу экрана | «Поделиться» и «Новое сравнение». Кнопки «Сохранить» там НЕТ |
| Сравнение как карточка | НЕ сохраняем. Учить нечего: у нас карточка — это русская сторона и немецкая |

## Откуда берутся факты (правило ноль)

Модель не сравнивает голые строки. Порядок жёсткий:

1. Каждое слово ищется в наших источниках: слой словарных статей (`bt_3_dictionary_entries`),
   справочник склонений, при промахе — Wiktionary (`_fetch_wiktionary_entry`).
2. Модели уходят НАЙДЕННЫЕ СТАТЬИ, а не слово. Сравнивать нечего — значит, сравнения нет.
3. Слово не найдено нигде → экран 6 макета: честно говорим, что не нашли, и предлагаем
   исправление, если оно очевидно (например, дореформенное «Vorschuß» → «Vorschuss»).
   Разбор НЕ запускается. Счётчик «не нашли» растёт и попадает в отчёт.
4. Артикль, множественное число и уровень у модели НЕ спрашиваются — только из наших источников.

## Что возвращает модель

Строгий JSON, каждое поле — свой блок экрана. Нет поля → нет блока, ничего не подставляем.

| Поле | Что внутри |
|---|---|
| `verdict[]` | По строке на слово: суть в 8–12 словах, без терминов |
| `interchangeable` | `no` / `sometimes` / `yes` + условие словами |
| `words[]` | `meaning_ru`, `when_ru` (когда берут), `where_ru` (где звучит), `partners[]` |
| `examples[]` | По верному примеру на слово (немецкий + перевод + чем отличается) и РОВНО один неверный с объяснением |
| `chooser[]` | Ситуация → слово |
| `trap_ru` | Ошибка именно русскоязычных и правило-подсказка |
| `collocations[]` | По два устойчивых сочетания на слово, ТОЛЬКО из поданных статей |

Правила промпта: сравнивать разрешено только поданные статьи; выдумывать значения, сферы и
сочетания запрещено; если данных на поле нет — поле пустое, а не заполненное догадкой.

## Что меняем в коде

**Фронт**
- `frontend/src/dictionary/DictionaryOverlay.jsx` — четвёртая вкладка, экран ввода, экран разбора.
- `frontend/src/App.jsx` — та же вкладка во внутреннем словаре.
- Общий компонент экрана разбора (новый файл `frontend/src/dictionary/WordDiff.jsx`) — чтобы
  два словаря не разъехались, как когда-то разъехалось правило языковой пары.
- `dict.css` — стили блоков; цвета берутся токенами, «Фукс» получает свой скин даром.

**Сервер**
- `POST /api/webapp/dictionary/diff` — разбор пары (кеш → источники → модель → запись).
- `POST /api/webapp/dictionary/diff/history` — свои сравнения.
- Промпт — рядом с остальными, в `backend/openai_manager.py`.
- Расход пишется на пользователя (`set_llm_billing_user`), как в `/dictionary/feel`.

**База**
- `bt_3_word_diff_cards` — общий кеш: ключ пары (слова по алфавиту + языки), JSON разбора,
  источники, дата, счётчик открытий.
- `bt_3_word_diff_history` — кто какое сравнение открывал и когда.

**Лимит**
- Новый код `word_diff_daily` = 3: сидирование в `database.py` (там же, где `feel_word_daily`),
  страж эндпоинта в `backend_server.py`, строка в `admin_economics.py`.
- Счётчик тикает ТОЛЬКО при новом разборе. Отдача из кеша не тикает.

**Сохранение** — ничего нового не пишем, используем существующую цепочку `saveChip`
(`DictionaryOverlay.jsx:1051`): галочка сразу → в фоне быстрый перевод + разбор →
`buildDictionarySavePayload` → `/api/webapp/dictionary/save` → один автоповтор при обрыве →
при провале галочка снимается и человек видит человеческий текст.

**Тесты (`backend/tests`)**
- слово не найдено → 404-состояние, модель НЕ вызывается, счётчик лимита НЕ тикает;
- второй запрос той же пары → приходит из кеша, лимит не тикает;
- ответ модели без обязательного поля → блок не показывается, ошибка считается;
- порядок слов в паре не создаёт второй записи кеша.

## Чего НЕ делаем

- Не сохраняем сравнение как карточку.
- Не выводим артикль/формы/уровень из ответа модели.
- Не показываем разбор, если хоть одно слово не найдено в источниках.

## Предложение (не работа — решение за владельцем)

Кеш разборов копится, и никто его не перечитывает. Предлагаю раз в неделю прогонять новые
записи вторым голосом модели и слать владельцу спорные — с кнопками «оставить / пересобрать /
выбросить», как сделано в приёмке артиклей. Это отдельная работа; без вашего слова не начинаю.
