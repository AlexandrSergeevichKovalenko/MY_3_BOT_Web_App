# Тариф «Лайт» и платный месяц: стратегия правки

Решения владельца, 04.09.2026 (все пять — «да»):

1. После 30 дней без оплаты человек видит только окно с двумя тарифами и настройки.
   Ежедневные задания в Telegram прекращаются.
2. У всех, кто уже есть в базе, 30 дней отсчитываются со дня деплоя.
3. Первые 7 дней — полный доступ (как сейчас), дни 8–30 — уровень Лайт бесплатно,
   с 31-го дня — оплата.
4. Напоминание о пропавшем доступе: раз в неделю 8 недель, потом раз в месяц.
5. Название тарифа — «Лайт», так и попадает в платёжное окно Telegram.

Цена: Лайт = 160 ⭐ за 30 дней (тот же курс, что у «Полного доступа» 400 ⭐ за 5 €;
нам приходит ≈ 1,9 €). Полный доступ не меняется.

---

## 1. Что есть сейчас (по коду, проверено 04.09.2026)

**Право доступа** считает одна функция `resolve_entitlement` (`backend/database.py`).
Она умеет ровно два состояния: `effective_mode = free | pro`. Все ворота в вебе и в боте
смотрят только на это поле. Третьего состояния «месяц кончился» нет.

**Первый вход.** Таблица `bt_3_user_identity` хранит `created_at`, и его никто не
переписывает: ни выход, ни блокировка бота, ни удаление личных данных. Но пишется она
из фонового потока «запомнить имя» и как источник для замка слаба: строка может не
появиться, и никто не заметит. Кроме того, таблица заведена 31.07.2026, для старых
людей дата в ней — не первый вход, а день заливки.

**Пробные 7 дней** — строка в `bt_3_pro_grants` с `reason='welcome_trial'`, ставится
при первом открытии приложения, одна на всю жизнь, не удаляется.

**Оплата звёздами.** Подписка «Полный доступ» уже сделана как подписка Telegram
(`subscription_period = 2592000`, ровно 30 дней). Счёт выписывает бэкенд
(`/api/webapp/billing/stars_invoice`), исполняет бот (`on_stars_successful_payment`),
просрочка ловится при чтении (+2 дня после `current_period_end`). Отмена чужой
подписки через Bot API (`editUserStarSubscription`) нигде не используется.

**Дверь в веб.** `enforce_webapp_access` (`backend_server.py:3762`) — единственное
место, через которое проходит каждый запрос `/api/webapp/*`. Там же уже отдаётся
спокойный экран «в очереди / доступ закрыт» через 403 с полем `reason`, а браузер
ловит его в одном перехватчике (`frontend/src/main.jsx:833`).

**Рассылка заданий.** Единой двери НЕТ. Три пути с собственной копией логики тарифа:
слоты (`_collect_quiz_delivery_user_targets`), капля (только платные), вечерний
добор (`_daily_topup_job`). Плюс кнопка «▶️ Следующее задание» (`_pull_budget_for`).
Все они узнают «бесплатный / платный» через `is_user_pro` → `resolve_entitlement`.
Отдельно шлют без всякой проверки тарифа: напоминание о карточках, напоминание об
ошибках 11:00, сертификаты, чемпион недели, дайджест 21:30, вечерние поздравления.

**Открытые для бесплатных команды в чате:** `/translate` (без всяких ворот), словарь
в чате (лимит в день), вставленный текст (15 в день), `/review`, `/interaktiv_test`.

**Экран при входе.** `ProTrialModal` знает два режима: `active` (идут 7 дней) и
`ended` (кончились, теперь Free). Показывается раз в день на состояние.

**Живая база 04.09.2026 (только чтение):**

| что | сегодня |
|---|---|
| людей в identity | 14 |
| из них старше 30 дней по created_at | 13 |
| активных за 7 дней (получали задания) | 13 |
| платных подписок | 1 |
| заблокировали бота | 2 |
| в списке допуска | 17 |
| без строки пробного периода (не открывали приложение) | 6 |

Вывод для решения №2: без «отсчёта с деплоя» замок закрылся бы в день выкладки для
13 из 14 человек.

## 2. Как это решено у других

- **Babbel, Lingvist, Seedlang** — пробный период, потом только платно. Наша схема.
- **Duolingo** — бесплатно навсегда, живёт на рекламе. Не наш случай.
- **Общее место у всех:** предупреждение за несколько дней до конца пробного (Apple
  этого даже требует для подписок App Store). Делаем плашку «осталось N дней» с 26-го дня.
- **Telegram Stars:** подписка всегда 30 дней, продление автоматическое, отмена в
  настройках Telegram. Сменить тариф Telegram не умеет — только отменить одну подписку и
  оформить другую. Это влияет на переход Лайт → Полный (см. §4.3).

## 3. Источник истины: начало отсчёта

Заводим отдельную таблицу, а не выводим дату из чужих столбцов:

```
bt_3_access_period
  user_id      BIGINT PRIMARY KEY
  started_at   TIMESTAMPTZ NOT NULL     -- первый контакт с нами
  source       TEXT NOT NULL            -- bot_start | signup | bootstrap | backfill_deploy | night_sweep
  created_at   TIMESTAMPTZ DEFAULT NOW()
```

Правила:

- Строка пишется **синхронно** в четырёх местах, где человек впервые появляется:
  `/start` в боте, первое сообщение в боте, самозапись по ссылке
  (`_grant_self_serve_webapp_access`), открытие приложения (`/api/webapp/bootstrap`).
  Всюду `INSERT … ON CONFLICT DO NOTHING`: первый писатель побеждает, перезаписи нет.
- **Никогда не обновляется и не удаляется.** Чистка личных данных
  (`purge_telegram_user_personal_data`) её не трогает — как и пробный период.
- **Заливка для существующих** (решение №2): при старте сервера для каждого известного
  человека (identity ∪ список допуска ∪ подписки) без строки ставится
  `started_at = ACCESS_PERIOD_BACKFILL_AT` — константа в коде с датой деплоя и подписью
  «решение владельца 04.09.2026». Идемпотентно.
- **Ночная страховка:** задача раз в ночь находит известных людей без строки и ставит
  `source='night_sweep'`, `started_at = now()`. Число таких строк — обещание
  `access_period_missing = 0`: если оно растёт, значит одна из четырёх дверей молчит.

Конец бесплатного месяца = `started_at + 30 дней`. Никаких «календарных месяцев»:
Telegram-подписка тоже 30 дней, и числа сходятся.

## 4. Право доступа: третье состояние

### 4.1 `resolve_entitlement` получает поле `access_state`

```
access_state ∈ { pro | light | free_month | locked }
free_month_ends_at   -- ISO или null
free_month_days_left -- целое
```

Как считается (по порядку, первый подошедший побеждает):

1. Платная активная подписка `pro` или действующая выдача (пробные 7 дней, бонусные
   дни) → `pro`. `effective_mode = pro`, как сейчас.
2. Платная активная подписка `light` → `light`. `effective_mode = free` (функции те же,
   что у бесплатного), `source_of_entitlement = paid_light`.
3. Нет подписки, `now < started_at + 30 дней` → `free_month`, `effective_mode = free`.
4. Иначе → `locked`, `effective_mode = free`.

`effective_mode` остаётся двухзначным: все существующие ворота продолжают работать без
правок. Замок — отдельное поле, и его читают только двери из §5.

Нет строки периода (не должно случаться, см. §3) → **не `locked` и не `free_month`**, а
отдельное состояние `unknown` со счётчиком и строкой в утреннем отчёте. Замок на
«не знаю» не вешаем: это была бы догадка против человека.

### 4.2 Тариф `light`

- Строка в `plans`: `('light', 'Лайт', is_paid=true, billing_type='recurring')`.
- Цена по той же формуле, что у Полного: `LIGHT_PRICE_EUR_MINOR=246` →
  `ceil(2.46 × 1.30 × 50) = 160 ⭐`. Проверено арифметикой: 2.46 × 65 = 159.9 → 160.
- `GET /api/billing/plans`: `amount_stars` для `light` из `light_price_stars()`.
- `POST /api/webapp/billing/stars_invoice`: ветка `light`, заголовок «Лайт — подписка»,
  `subscription_period = 2592000`, `payload = {purpose: 'light', user_id}`.
- Бот `on_stars_successful_payment`: ветка `light` зеркалит `pro`
  (`set_subscription_from_stripe(plan_code='light', stripe_subscription_id='stars_<charge>')`),
  подтверждение: «✅ «Лайт» подключён — задания приходят как раньше. Продлевается раз в
  30 дней, отменить можно в настройках Telegram».
- Просрочка: та же проверка `stars_` + 2 дня, что у Полного.
- Возврат (`revoke_star_payment_fulfillment`): ветка `light` = деактивация подписки.

### 4.3 Переход между Лайт и Полным

Telegram не умеет «сменить» подписку. Поэтому:

- **Лайт → Полный:** человек платит Полный. Бот при исполнении видит активную подписку
  `light` с `stars_<charge>` и вызывает `editUserStarSubscription(is_canceled=true)` для
  неё, чтобы через 30 дней не списалось второе. Лайт остаётся до конца оплаченного
  периода, но не мешает: Полный перекрывает.
- **Полный → Лайт:** пока Полный активен, карточка Лайт на экране «Подписка» неактивна
  с подписью «У вас уже Полный доступ. Отмените его в настройках Telegram, и после конца
  периода можно оформить Лайт». Двойной оплаты не даём.
- Если отменить чужую подписку у Telegram не вышло (ошибка API) — подписка Полного всё
  равно выдаётся, ошибка логируется, и случай уходит владельцу письмом с кнопками
  «вернуть звёзды за Лайт» / «оставить как есть» (шаг 8 цикла).

## 5. Двери замка (где `locked` действует)

Одна проверка `is_access_locked(user_id)` (кешируется 10 минут, как `is_user_pro`),
применяется в трёх местах — и только в них:

### 5.1 Веб: `enforce_webapp_access`

После того как человек опознан и допущен: если `locked` и путь не в белом списке →
`402 {error: 'access_locked', reason: 'free_month_over', light_stars, pro_stars}`.

Белый список (то, что нужно, чтобы заплатить и не потерять настройки):
`/api/webapp/bootstrap`, `/api/webapp/billing/*`, `/api/billing/plans`,
`/api/webapp/settings/*`, `/api/webapp/onboarding/*`, `/api/webapp/instance/*`,
`/api/webapp/webapp/version`-подобные служебные. Список — константа рядом с дверью, с
тестом «каждый путь из списка отвечает 200 запертому».

Это единственное место: гейтить каждую функцию по отдельности не будем — так двери
и теряются (см. §1, «единой двери нет»).

### 5.2 Бот: рассылки

`list_access_locked_user_ids()` вычитается там же, где вычитаются заблокировавшие бота:
в `_collect_scheduler_candidate_user_ids` (через него идут слоты, добор, напоминание
о карточках, чемпион). Отдельно тот же вычет в путях, которые собирают людей своим
SQL: напоминание об ошибках 11:00, сертификаты, дайджест 21:30, вечерние поздравления,
личная аналитика. Капля не трогается: она и так только для платных.

Кнопка «▶️ Следующее задание» (`_pull_budget_for`) для запертого отвечает не задание, а
короткий текст с двумя кнопками оплаты.

### 5.3 Бот: команды с учебным содержимым

В начале `handle_user_message`, а также в `/translate`, `/review`, `/interaktiv_test`:
запертому — тот же короткий текст с двумя кнопками (Лайт 160 ⭐ / Полный 400 ⭐,
ссылки `startapp=buylight` / `startapp=buypro`). Оплата, `/start`, `/help`, настройки,
ответ на счёт — работают.

**Обещание в реестр:** `locked_users_got_learning_content = 0` — строк в
`bt_3_interactive_inbox` и в журнале словаря/переводов у запертых людей за вчера.

## 6. Экраны

### 6.1 `bootstrap` отдаёт блок `access`

```
access: { state, free_month_ends_at, days_left, light_stars, pro_stars }
```

### 6.2 Окно при входе (`ProTrialModal` → расширяется, не переписывается)

| режим | когда | закрывается? | кнопки |
|---|---|---|---|
| `active` | дни 1–7 | да | «Здорово, пользуюсь» (как сейчас) |
| `ended` | дни 8–25, 7 дней кончились | да, раз в день | «Оформить полный доступ» (как сейчас) |
| `month_ending` | дни 26–30 (`days_left ≤ 5`) | да, раз в день | «Лайт 160 ⭐», «Полный 400 ⭐», «Позже» |
| `locked` | день 31+ без подписки | **нет** | «Лайт 160 ⭐», «Полный 400 ⭐», ссылка «Настройки» |

В режиме `locked` приложение открывает раздел «Подписка», окно висит поверх, остальные
разделы недоступны. Перехватчик 402 в `main.jsx` — страховка: если окно по какой-то
причине не показалось, любой запрос его поднимет.

### 6.3 Экран «Подписка»

- Сравнительная таблица из двух колонок становится тремя: **Лайт** (первый месяц
  бесплатно, дальше 160 ⭐), **Полный доступ** (400 ⭐). Колонка «Free» исчезает как
  название: бесплатного тарифа больше нет, есть бесплатный месяц Лайта.
- Карточки из каталога: добавить `light` (порядок между free и pro), `handleBillingUpgrade`
  принимает `light`, `startapp=buylight` запускает оплату так же, как `buypro`.
- Статус: «Лайт до 12.10», «Полный доступ до …», «Бесплатный месяц до …», «Доступ
  приостановлен».

### 6.4 Онбординг, шаг «Тарифы»

Заголовок «Тарифы: Лайт и Полный доступ». Блок про пробный период переписать одной
фразой: «Первые 7 дней — полный доступ. До конца первого месяца — Лайт бесплатно.
Дальше Лайт 160 ⭐ / 30 дней или Полный доступ 400 ⭐ / 30 дней.» Цены — из
`/api/billing/plans`, не в коде (там уже стоит запрет на захардкоженную цену).

### 6.5 Тексты

Никаких «Free» и «Pro» в новых строках. «Лайт», «Полный доступ», «бесплатный месяц».
Немецкие зеркала: «Light», «Voller Zugang», «Gratismonat».

## 7. Напоминание в Telegram (решение №4)

Задача бота по образцу напоминания о карточках (`send_flashcard_reminder`):

- **Кому:** `access_state = locked`, бот не заблокирован, подписки нет.
- **Когда:** суббота 11:00 Europe/Vienna, вне часов тишины.
- **Как часто:** таблица `bt_3_access_reminders (user_id, sent_at, seq)`. Правило:
  `seq ≤ 8` — не чаще раза в 7 дней; дальше — не чаще раза в 30 дней. Источник
  каденса — эта таблица, не память процесса.
- **Что:** картинка в стиле Fuchs UI (`backend/access_reminder_card.py`): «Ты занимался
  с нами месяц. Чтобы задания приходили дальше: Лайт 160 ⭐ или Полный доступ 400 ⭐».
  Две inline-кнопки → `startapp=buylight` / `startapp=buypro`.
- **Стоп:** оплатил → строк больше не шлём (проверка состояния перед каждой отправкой).

**Обещание:** `access_reminders_over_cadence = 0` — людей, получивших два напоминания
с интервалом меньше положенного.

## 8. Автомат, письма владельцу, отчёт (шаги 7–9 цикла)

- **Ночью:** страховка §3 (люди без строки периода), проверка обещаний (уже есть).
- **Утренний отчёт** получает строку «🔒 Доступ: бесплатный месяц N · Лайт N · Полный N ·
  заперто N · за вчера оплат Лайт N / Полный N».
- **Письма с кнопками** (не чаще раза в неделю, пачкой): (а) не удалось отменить
  подписку Лайт при покупке Полного (§4.3); (б) человек заперт, но у него есть строки
  выдачи за вчера — нарушенное обещание, кнопки «держать» / «снять» (механизм уже есть).
- **Проверка руками в моменте:** `/admin_access <user_id> [дата]` — показать состояние и
  для тестового аккаунта передвинуть `started_at` назад. Именно так снимается снимок
  экрана «после» для замка, не дожидаясь 30 дней.

## 9. Что чистим в базе и что не трогаем

- **Чистить нечего:** состояния «заперт» ещё не существует, испорченных записей нет.
- **Заливка** периода для существующих (§3) — единственная запись в накопленное.
- **Не трогаем:** подписку единственного платящего, пробные выдачи, лимиты бесплатного
  уровня (они становятся лимитами Лайта без изменений), формулу цены Полного.

## 10. Порядок выкладки

1. Таблица периода + заливка + четыре двери записи + ночная страховка + обещание
   `access_period_missing`. Поведение не меняется.
2. Тариф `light`: план, цена, счёт, исполнение, просрочка, возврат, отмена Лайта при
   покупке Полного. Купить Лайт можно сразу, замка ещё нет.
3. `access_state` в `resolve_entitlement` + блок `access` в bootstrap + экраны
   (окно, «Подписка», онбординг) + `handleBillingUpgrade('light')`.
4. Двери замка (§5) + перехватчик 402 + обещание `locked_users_got_learning_content`.
   Для существующих людей замок сработает через 30 дней после шага 1, для новых — через
   30 дней после первого входа. Отдельного флага не нужно.
5. Еженедельное напоминание + строка в отчёте + письма с кнопками + `/admin_access`.

Каждый шаг — отдельный коммит на `agent/light`, тесты в `backend/tests`:
состояния права доступа (4 состояния + `unknown`), дверь веба (402 на запертом,
200 на белом списке), ветка `light` в счёте и исполнении, вычет запертых в сборщике
бота, каденс напоминаний.

**Снимок «после»** (обязателен для сдачи): тестовый аккаунт, `started_at` сдвинут на
31 день назад командой из §8 → скриншот окна `locked` в приложении, ответ бота на
«▶️ Следующее задание», отсутствие строк в `bt_3_interactive_inbox` за день, письмо
с картинкой и двумя кнопками.
